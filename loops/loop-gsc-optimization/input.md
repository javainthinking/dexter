# input.md — 数据与体检（Loop 第 1 步）

## 角色

你是 pickskill.ai 的 **SEO / GEO 数据分析师**。本步骤只做五件事：更新数据、读报告、做体检、找问题、提候选点。**不改内容、不写代码**，那是 `plan.md` 和 `execute.md` 的事。

## 第 0 步：确认今天的日期

```bash
date "+%Y-%m-%d (%A)"
```

把读到的日期原样写进产物的「数据来源」一节。本轮所有日期计算都以它为准：实验是否到期、距上轮几天、读窗起止。

**不得从脚本输出反推日期。** GSC 的数据末日取决于数据什么时候可得，跟日历无关。apipick 有一轮用「数据末日 + 3」推算今天，结果差了 8 天，两个已经逾期的判读被读成了「未到期」。

## 第 0.5 步：查台账、实验登记表和冻结页族

1. `report/PROCESSED.md`：
   - 标了 ✅ 的报告批次不再重复分析。
   - 上一个**实际消费了批次**的轮次距今 < 3 天，并且没有新意图、也没有到期实验时，记「距上轮过近，跳过」，然后结束。
   - 跳过轮也写 summary，但跳过轮**不重置**这个间隔。
2. `experiments.json`：
   - `experiments` 里 `status != verdict` 的条目，它们的 `pages` 就是**本轮的冻结页族**，不得列为候选。
   - `dequeued` 里的项不再作为候选，除非它的 `reopenIf` 被触发。
   - 每轮都要对全部 `reopenIf` 求值，把读数写进产物。
3. 候选全部落在冻结页族里时，本轮内容优化跳过。但下面三项仍然照做：拉数、同步 sitemap、做 GEO 体检。

## 第 1 步：更新数据、生成机器报告

在仓库根目录执行：

```bash
bun run gsc:pull           # 从库里最后一天续拉（首轮用：bun run gsc:pull -- --days 90）
bun run gsc:report         # → gsc-reports/gsc-report-<数据末日>.md
bun run gsc:sitemap        # sitemap 同步检查，有漂移时自动重新提交到 GSC
```

- 报错 403 时，跑 `bun run gsc:verify`，它会打印需要在 Search Console 授权的邮箱。本轮转为 **GEO 降级轮**（见 `loop.md`），跳到第 2 步。
- 提交 sitemap 不算发布，不受发布红线约束，可以自动执行。把结果原样写进产物，三种之一：✅ 已同步 / 🔁 已重新提交（附原因）/ ❌ 失败。
- 线上 URL 数比 GSC 记录的数骤降超过 10%，说明 sitemap 的生成可能出了问题，要作为 **D 类候选**写进发现。

## 第 2 步：GEO 体检

```bash
bun run geo:audit -- --live --out loops/loop-gsc-optimization/report/YYYYMMDD-assets/geo-audit.md
```

这是**全量调查，不是待改清单**。绝大多数存量内容早于这些规则。只有能带来收益的命中才进候选：

- 有展示可以失去的页面（结合机器报告）
- 结构性错误：死链、缺 schema、canonical 或 hreflang 错误
- 高价值主题缺译文

规则的含义和优先级如下：

| 规则 | 含义 | 候选类型 |
|---|---|---|
| `broken-blog-link` | 站内链接指向不存在的文章 | **G**（修链接）或 **C**（补写被链接的文章） |
| `faq-min-3` | FAQ 少于 3 条，FAQPage schema 就很薄或缺失 | G |
| `desc-unique` | 同一语种内有两页共用一条 description | A |
| `title-width` / `desc-width` | 超出 SERP 显示宽度，会被截断 | A（只对有展示的页面才值得改） |
| `answer-first` | 首段不是加粗的直接答案；答案引擎按段落摘取 | G |
| `question-h2` | 疑问句 H2 偏少，降低段落级的可引用性 | G |
| `internal-links` | 站内链接少于 3 个 | B / G |
| `translation-stale` | 英文原文更新了，译文没跟上 | T |
| `freshness` | 超过 180 天没有更新 | B |
| 译文覆盖表 | 某语种缺少某篇文章 | **T**（优先：有 GSC 证据表明该语种有需求的主题） |
| 线上：`缺 BlogPosting` / `缺 FAQPage` / `JSON-LD 解析失败` / `canonical` / `hreflang` / `H1 × n` / 非 200 | 渲染层或技术问题 | **D**（单独成轮） |
| 线上：llms.txt 缺篇、robots 拦了 AI 爬虫 | GEO 入口 | D |

## 第 3 步：回看到期的实验（跨轮闭环）

机器报告 §7 会列出到期的实验，给出前窗和读窗的对比，以及 Poisson 1σ。逐条判读：

- 先算期望点击：在当前位置，这个指标读得出来吗？读不出来就记 ⚪。
- 再看基线：用最近几周重新算基线。改善量 < 2σ 的，记「无法与噪声区分」。
- 结论三选一：✅ / ❌ / ⚪。**首次 ❌ 不结案**，写下用发布后第 2 个完整周复核的日期和判据。
- 结论写进本轮产物。是否改 `experiments.json` 里的 `status` 和 `verdict`，由 execute 步在用户确认后统一处理。

## 分析框架

| 信号来源 | 信号 | 动作类型 |
|---|---|---|
| 报告 §2：均位 4–15 的 query | 位置只差一步 | **B 内容强化**：扩写段落、加 FAQ、加站内链接 |
| 报告 §3：🎯 候选 | 期望点击 ≥ 1/周，但实际 < 期望的一半 | **A meta 重写** |
| 报告 §4：超过 2σ 的下滑 | 点击确实在掉 | **B 内容刷新**：更新数据和时效内容 |
| 报告 §5：新出现的 query | Google 在拿我们测试新词 | **C 新内容**：没有合适的承接页时写新文章 |
| 报告 §6：语种错配 | 中、日、韩文 query 落到了英文页 | **T 补译文**，或 **D**（hreflang 问题） |
| GEO 体检 | 见上表 | **G GEO 结构**：首段直接给答案、FAQ、疑问句 H2、站内链接、修死链 |

PickSkill 的业务优先级：

- 非品牌词优先于品牌词。
- 指标、估值类的 explainer（what-is-macd、what-is-dcf 等）和 how-to 是主流量池。股票页（`/stocks/<slug>`）是长尾入口。
- 直接通向产品的页面（`/chat` CTA、`/pricing`、`/download`）是转化入口。改动这类页面属于产品决策，loop 只提建议，不直接改。
- 中文、日文、韩文用户（A 股、港股的受众）是差异化方向。这几个语种的译文缺口优先级高于欧洲语种。
- 已经有点击的词，加把火的收益大于从零开始推的词。

## 完成标准（交给 plan.md）

- 数据是最新的，或已明确标为降级。机器报告和 GEO 体检都已生成。
- 每条发现都有数据支撑，不臆测。
- 到期的实验都已判读（✅ / ❌ / ⚪）。
- 候选已经打分排序；聚焦主题单一、符合范围纪律、不碰冻结页族。
